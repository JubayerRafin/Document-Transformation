TransformX runtime investigation and optimization
18 October 2026

The saved six PDF Deep Doc batch took 1243.6 seconds. Its recorded stages were
620.6 seconds for translation and reconstruction, 391.2 for image processing,
222.8 for extraction and 9.0 for validation. There were 176 completed model
requests with 204.3 seconds of recorded request time, including nested figures.
Request time is not an independently measured GPU kernel time. The unassigned
remainder includes parsing, model initialization, process startup, transport,
scheduling, rendering, fitting and file work; old logs cannot separate it all.

Nine saved completed OCR workers report 36.21 seconds in total. Their timers
exclude laptop preparation, SSH setup and transfers, status polling and figure
PDF reconstruction. Do not add these times to the already inclusive stage times.

Implemented changes

1. The production source extraction defers the legacy figure pass because the
   spatial render and mask pass replaces those candidates immediately afterward.
   Direct extraction callers retain the old behavior by default. A regression
   test compares final figure pixels, boxes and text on an unseen fixture.
2. Docling converters are reused per process with fixed CPU and no OCR policy.
   Construction and conversion are serialized. Per page geometry and errors
   remain on each adapter. Actual initialization and reuse are recorded.
3. GPU OCR sends its source and three allowlisted workers in one tar upload
   over one SSH connection and starts the detached worker afterward. Result
   download, source hashing, strict host checks, timeout and scoped cleanup stay
   in place. Actual remote execution of this transport still needs the GPU test.
4. The BabelDOC layout hook reads source image, table and strict cell geometry
   once per invocation and reuses it in before and after audits.
5. runtime-timing.jsonl records source extraction, OCR handoff, spatial figure
   analysis and nativeized extraction. transport-timing.json separates upload,
   polling and download; Ollama transport events retain load, prompt and decode
   duration counters. These logs do not include prompt or response content.
6. Nested OCR errors are printed to the remote worker log. Batch errors now
   retain the original processing failure before the secondary GPU warning.
7. OCR cache policy can be explicitly reuse or fresh. Translation cache remains
   disabled by the dataset runner so fresh model requests are still measured.

thread reuses one HTTP connection for sequential Ollama requests. Endpoints
