Extraction and IR responsibilities
The laptop profiles each page before detailed extraction. Searchable text uses native PDF evidence and Deep Doc pdfplumber adaptation. Docling supplies structural table candidates, with Camelot or pdfplumber fallbacks where appropriate. Native text coverage and geometry guards may reject candidates. Scans and selected raster figure content use PaddleOCR on the remote GPU. Render and mask candidates are heuristic and require inspection.

There are two distinct representations. TransformX source-ir.json is the shared content IR for regions, coordinates, tables, assets and context. BabelDOC retains its own detailed PDF IR for glyph geometry, translation layout and reconstruction. The LLM receives selected text and bounded context, not both complete IR documents. The LLM does not draw the PDF.

For PII only, source regions from TransformX IR go to the PII detector. The redactor applies findings to the source PDF. BabelDOC translation is not required for this PDF route. Scan and figure workers can redact raster content. Verification extracts or OCRs the resulting artifact again, so transformed-ir.json is output evidence and should not be confused with a second instruction document sent to the LLM.

Artifact | Purpose
document-analysis.json | Page profile and routing evidence
deep-doc/extraction-evidence.json | Actual engines, accepted and rejected candidates
source-ir.json | Source text, region IDs, page boxes and assets
pii-findings.json | Detected literals, categories, offsets and methods
redaction-audit.json | How each source finding was located and removed
transformed-ir.json | Content extracted from the generated artifact
independent-validation.json | Residual values, geometry and uninspected content
privacy-verification.json | Fresh rendered output OCR checks when invoked
output/result.pdf and manifest.json | Final artifact, settings, status and limitations

Install the local environments
Extract the ZIP into a short folder, such as C:\TransformXTeam. Open the project subfolder in VS Code. Run all following PowerShell commands from that project folder. Use Python 3.11 for local environments; the GPU installer uses the pod Python. Keep the BabelDOC environment separate to avoid dependency conflicts.

py -3.11 -m venv .venv-paddleocr
.\.venv-paddleocr\Scripts\python.exe -m pip install -r requirements.txt -r requirements-deep-doc.txt

py -3.11 -m venv .venv-babeldoc
.\.venv-babeldoc\Scripts\python.exe -m pip install -r requirements-transformation.txt

py -3.11 -m venv .venv-evaluation
.\.venv-evaluation\Scripts\python.exe -m pip install -r requirements.txt -r requirements-evaluation.txt

The app environment needs extraction packages, while the evaluation environment can read saved evidence and compute detailed metrics. COMET is optional for translation and is not a PII metric. Model weights, virtual environments, credentials and third party caches are deliberately excluded from the ZIP. Native Office export may also need LibreOffice and is outside the six PDF PII experiment.

Initialize the portable experiment once

.\.venv-paddleocr\Scripts\python.exe -m tools.handoff.initialize_pii

The initializer verifies the six source hashes, relocates path fields in the copied run evidence and writes configs/pii-team.local.json. It records the original experiment fingerprint and calculates a local fingerprint for the relocated policy. It does not rerun translation or transfer human approvals. The untouched original index and manifest copies remain under evidence/.

The completed translation index is included because the current batch runner requires a completed translation phase before its PII phase. This is an experiment sequencing guard, not a dependency on translated PDFs: PII starts again from the original sources. Do not run prepare on an initialized package because it can replace the registered source metadata. Do not change policy or runtime source code after creating PII annotations; use a new experiment root if the code changes.

Connect the GPU and run PII
Use your own pod address, SSH port and private key. Do not reuse Jubayer connection details. Verify nvidia-smi and HTTPS downloads inside the pod before installation. Upload tools/gpu/setup_transformx.sh through scp, then run the following Linux command inside the root prompt.

bash /workspace/setup_transformx.sh pii

Wait for Setup finished. The installer checks CUDA tensor placement and convolution with numerical tolerance, installs PaddleOCR, and caches the detector and recognition models. A successful pip installation alone is not a successful OCR setup. The pii option pulls Qwen; all also pulls TranslateGemma.

In a separate Windows PowerShell terminal, open the tunnel and keep it running. Replace each placeholder with your actual value.

ssh.exe -N -o ExitOnForwardFailure=yes -o ServerAliveInterval=30 -p SSH_PORT -i "PRIVATE_KEY_PATH" -L 127.0.0.1:11435:127.0.0.1:11434 root@GPU_IP

Edit configs/pii-team.local.json: endpoint stays http://127.0.0.1:11435/v1; pii_model stays qwen3.5:9b; fill ocr_remote.host, port and key. Keep table_strategy set to docling for this experiment. All six supported categories are selected. Keep visual analysis off, manual protected values empty and context empty for the registered baseline. Protected values are translation preservation settings, not PII exemptions.

.\.venv-paddleocr\Scripts\python.exe -m tools.evaluation.dataset preflight --config configs/pii-team.local.json --phase pii
.\.venv-paddleocr\Scripts\python.exe -m tools.evaluation.dataset run --config configs/pii-team.local.json --phase pii

For an interrupted unchanged experiment add --resume to the run command. Inspect the first source and redacted output as soon as it finishes. The runner checks model VRAM evidence; a failure before model inference can produce a secondary GPU verification warning. Read the original error and the nested OCR detection or recognition log. Stop the paid GPU when inference is complete; retained storage may still be billed.

How to annotate PII ground truth
After PII execution, review templates are written to ground-truth/Sample01.pii.json through Sample06.pii.json under the initialized batch. review-bundles/SampleXX/pii contains rendered source and output pages plus regions.csv. Use the PII source IR from that run; extraction and region IDs can differ from the translation run. Never copy translation region IDs or the model findings into the gold labels without checking the original page.

For every region, compare extracted_text with the original PDF, enter an independently checked source_reference and set source_reviewed=true only when verified. Put each sensitive occurrence into the region pii array. Offsets are zero based Python character positions, with start included and end excluded. They refer to extracted_text, not the corrected source_reference.

Example extracted_text: "Contact Maya"

"pii": [
  {"start": 8, "end": 12, "value": "Maya",
   "category": "Names"}
]

Required invariant:
extracted_text[start:end] == value

Category string | Annotation scope
Email addresses | Visible email occurrences
Phone numbers | Phone and extension values under the agreed policy
Names | Person names under the agreed policy
Addresses | Personal location or address spans
Identifiers | Sensitive IDs under the agreed policy
Bank accounts | Account values under the agreed policy

Before labeling, agree whether employee IDs, salary, signatures, company addresses and document numbers are in scope. The current six categories are not a complete organizational privacy policy. Record ambiguous cases and apply one consistent decision across all PDFs. Mark empty pii arrays as reviewed negatives only after checking the whole region.

Put PII visible on the page but absent from extracted text into missing_source_regions, including page, box, visible text and category. Record visible residuals in privacy_residuals and unnecessary masking in over_redactions. Set pii_ground_truth_reviewed, source_coverage_reviewed, visual_reviewed and privacy_reviewed only after their respective checks are complete. Do not set human_accepted merely because the output opens.

Evaluate detection and actual removal
Run the detailed evaluator after filling all six PII ground truth files. Do not run COMET for PII; it evaluates translation meaning rather than entity detection or removal.

.\.venv-evaluation\Scripts\python.exe -m tools.evaluation.detailed evaluate --config configs/pii-team.local.json --phase pii

Read pii/detailed/report.html, report.json and summary.csv under the batch folder. These are the authoritative region based PII metrics. The simpler dataset report uses a separate annotations.json schema; do not assume populating ground-truth automatically populates that older form. Prefer the detailed report for the teammate deliverable.

Metric or check | Interpretation
Exact span precision | TP / (TP + FP); correct region, category and exact offsets
Exact span recall | TP / (TP + FN); misses on annotated extracted text
Exact span F1 | 2PR / (P + R); report counts and scores per document
Overlap span score | One to one overlapping spans in the same region and category
Per category scores | Separate the six classes so weak classes are visible
CER and WER | Reviewed source transcription versus extracted text; OCR quality
Privacy residual review | PII remaining in visible pixels, text or hidden content
Over redaction review | Useful non sensitive content unnecessarily removed
Layout preservation | Page geometry, figures, clipped text and affected tables

Report macro and micro aggregates only if explicitly implemented and verified. Existing detailed reports provide per document and per category scores; do not invent a pooled percentage. True negatives are not defined for arbitrary text spans, so a generic accuracy percentage is misleading. Show TP, FP and FN. With no gold or predicted spans, inspect denominators and label a reviewed negative explicitly.

Detection F1 measures only extracted regions. It can be high even when OCR missed a sensitive address in an image. Actual removal must therefore be checked independently against original pages, rendered redacted pages, searchable text, metadata and attachments. Fresh rendered OCR is useful but can also miss text. No automated check in this snapshot certifies complete anonymization.

Known limitations to investigate

The six PDF PII model experiment is unvalidated. Email and phone patterns are limited, and semantic names or IDs may require more context. Scans currently redact an entire detected line, which can remove useful content. Figure candidates can overlap native text and remain blocked. Sample01 OCR is uncertain; Sample04 has image and layout issues in the translation run. Those translation findings are risk examples, not automatically verified PII defects.

Check the verification language in PII only mode: privacy_verification.py currently passes options.target to fresh OCR even though the unchanged source language may be English. Also audit child figure findings: some are saved under nested figure runs and should not be silently omitted from end to end accounting. Treat the manifest field pii_detection_complete=false as a stated completeness limitation, not a reason to set it true manually.

These local tests cover operation routing, synthetic redaction, annotation provenance and metric behavior. They do not replace real Qwen GPU inference or a reviewed privacy dataset.
